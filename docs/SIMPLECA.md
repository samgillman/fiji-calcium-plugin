# SimpleCa²⁺ inside Fiji

Step 4 analyzes one measured recording locally. Version 2026.11.20.3 combines the browser/movie workflow from version 2026.11.20.2 with portable response protocols, exact timestamps, persistent ROI identities and explicit analysis provenance. The browser page and native Fiji fallback use the same pinned R engine.

## Where Step 4 opens

**Open analysis page** opens Step 4 in your default browser. Fiji serves the page on your own computer, through a loopback address with a random session key. No recording data is uploaded. Keep Fiji open while using the page. Each measurement gets its own page and private input snapshot; remeasuring or closing the cell-selection window does not shut down earlier review pages. Use **Close analysis** in a page to release its session and temporary inputs, or quit Fiji. Browser tabs begin with the cell count and include a session identifier. Engine setup and update downloads require internet; an already installed engine and the local page can run offline.

The browser adds trace hover/selection and time-axis zoom, sortable tables, and an interactive heatmap. **Use a Fiji window instead** opens the native analysis window, which is also the fallback when a browser cannot be opened. Both views include recording playback, frame scrubbing, linked traces and a heatmap, and preserve the protocol, QC and measurement definitions below.

If you change the accepted cells or measure again, review the new measurement before analyzing it. A completed result remains associated with its own input, ROI and protocol snapshots; draft settings or a newer measurement must not be read as the settings of an older result.

## Preview the recording before analysis

When the recording is available, the browser opens in **Recording** view. The playback controls are at the top of the review area: **Play**, previous/next frame, the frame slider and **Speed**. They work before an analysis has been run and do not require the R engine to be installed. The page says **Preview · no analysis yet**; response-percentage tiles, trace results and result tables appear only after a completed analysis.

Playback follows the available frame times on a clock in recording seconds: at **1×** a frame is shown when its timestamp is reached, and the other speeds (0.5× to 50×, **10×** by default) scale that clock. Above 30 frames per second on screen, every second, third or later frame is shown, and the frame note says so. A long gap between recorded frames waits at most about one second. Frames are loaded a few seconds ahead and kept, so scrubbing back over frames already seen is immediate; if loading falls behind, the picture holds and the note says **buffering** instead of the clock running ahead. While playing, the trace cursor moves continuously with the clock. Before timing has been confirmed, estimated seconds are marked as provisional. With no valid time base, the page explicitly labels a frame-by-frame preview whose **1×** rate is **20 frames per second**. That fallback is a display rate, not an inferred acquisition rate and not timing suitable for analysis. The frame/time label identifies what is being reviewed.

**View → Colour overview** shows the Step 2 overview, which does not move. Play and speed are disabled in that view. Before results exist, the slider and frame-step buttons are also disabled; after analysis, they can inspect the trace cursor while the overview remains static. Choose **Recording** to play or scrub actual movie frames. **Change from baseline** displays baseline-subtracted frames. These viewing choices do not alter measured values or response calls.

## Choose cells and measure

Choose identifiable cells independently of whether they brighten. In Step 2, **Picture** switches between **All frames** (the original colour picture), **Before response** (a frame range before the stimulus that you confirm) and **Response** (the response in magenta). Magenta is an optional review aid: it starts off, and choosing it looks for the response at that moment, as the first screen's option does. The picture changes in place, so outlines and clicks keep working. The selection basis is recorded. Cellpose suggestions and grades still require review; accepting only brightening cells would change the population whose response percentage is reported.

**Measure and save** writes stable IDs into the accepted ROIs and their measurement columns. An accepted-ROI registry records each ID, geometry hash, measured status, edge exclusion, background pixel count and selection basis. A separate accepted-ROI ZIP includes accepted outlines excluded before measurement. Those exclusions remain visible in the cohort flow; they are not silently relabeled as nonresponders. Editing any accepted outline, edge policy or selection basis requires measuring again before opening Step 4.

The analysis input is the full-precision `gray_values_background_corrected_native.csv`, containing the original cell mean minus its local background once. The older three-decimal CSVs remain available for compatibility. The intensity-lifted `for_SimpleCa_every_cell_kept.csv` is a legacy diagnostic export: an arbitrary offset changes fractional amplitudes and thresholds, so do not use it for ΔF/F₀ responder percentages.

## First use and timing

1. Click **Open analysis page**, then **Set up analysis engine**. A checksum-verified micromamba launcher installs private R 4.5.2 and jsonlite 2.0.0 from conda-forge. Supported runtime targets are 64-bit Windows, Intel/Apple Silicon Mac and x64 Linux. No system R installation or administrator access is required.
2. Confirm **frames per second** against acquisition metadata, or use **Load timestamps CSV**. Constant FPS puts frame 1 at zero; it cannot identify dropped frames. A timestamp file needs a `Time_s` column and exactly one finite, nonnegative, strictly increasing value per measured frame. Optional `Frame` must be 1, 2, … in order. The timestamp file is snapshotted and its checksum is checked before analysis.
3. Enter **Stimulus after frame**, the last frame before the stimulus was added. **F₀ frames**, **Baseline** and **Response window** follow it (see Stimulus timing); set them yourself only to match your actual timing. The page warns when F₀ frames come after the stimulus. The F₀ frames create the global trace `(F−F0)/F0`. The **Baseline** of each stimulus is the reference for its own response call. In the Fiji window, set **Baseline frames** for F₀ and each row's baseline, onset and response times in the protocol table.
4. Choose or load a protocol, inspect each row and any imported field timing overrides, and enter condition and independent biological-unit IDs when known. Check the timing/selection confirmation and click **Run analysis** in the browser, or **Analyze responses** in the native fallback.

Setup needs internet and disk space for R and downloaded packages. It is separate from Cellpose and stored under `.calcium-simpleca` in your home folder. A previous base-only R environment is not reused as protocol-ready: setup verifies the required R and jsonlite versions. Retry uses the package cache, and later analyses can run offline. Cancelled setup may leave partial installation directories, but it never marks them ready.

## Stimulus timing

Each stimulus has one **Stimulus after frame**, the last frame before the stimulus was added. The **Baseline** and **Response window** rows, and for the primary stimulus the **F₀ frames**, follow it by default and show their frames on a dashed chip; the primary stimulus's Baseline takes the F₀ frames and reads "same as F₀". A click on a chip gives two boxes to set that row yourself, and **auto** makes it follow the stimulus again. **Use frame** puts the movie frame on screen in **Stimulus after frame**, and rows that follow it move with it.

Under the rows, one line gives the Baseline, the stimulus and the Response window in seconds. Each row includes its first and last frame. The same windows are drawn under the frame slider. **F₀ frames** set the zero for ΔF/F₀; the **Baseline** sets how large a rise must be. When two rows disagree, the message sits beside the row to change and offers the repair.

## Response protocols

Each stimulus has its own response rule: the primary stimulus and, optionally, one named positive control. ATP, capsaicin, KCl, ionomycin or another control name is metadata; the software does not infer stimulation concentration or an optimal threshold from that name. This version supports one primary window and at most one control window. The browser keeps timing and the rule visible; click the **Rule:** line under a stimulus for the threshold, duration and noise floor settings. **Labels for the output** and **Advanced**, which holds recorded timestamps, the rule type and protocol file and the diagnostic files, expand when needed. In the native fallback, scroll the protocol table horizontally to inspect every setting. Unedited suggested values retain their underlying precision.

| Setting | Meaning |
|---|---|
| Baseline start/end | Local reference interval `[start,end)`, ending at or before application onset |
| Applied onset | Recorded stimulus application time; the reference for latency |
| Response start/end | Response window `[start,end]`, both ends included, beginning at or after onset |
| Minimum rise | Increase above the local baseline. The browser's percentage field displays `10` for 10%; the protocol stores this as the fraction `0.10` |
| Baseline SD multiplier | Multiplies the cell's noise, expressed as a fraction of the local reference (see **Noise** below) |
| Persistence | Actual timestamp span in `seconds`, or consecutive sample count in `samples` |
| Maximum gap | Largest consecutive timestamp gap allowed; blank uses the engine's declared automatic gap rule |
| Minimum baseline samples | Required finite samples in the local reference interval |
| Noise floor | Optional minimum baseline noise. Browser percentage fields are converted to the protocol's fractional units; this setting does not exclude a cell |
| Expected interval | Optional declared sampling interval used by coverage/gap checks |

The threshold is `max(minimum rise, SD multiplier × noise)`, with the optional noise floor applied before multiplying. Samples equal to the threshold qualify (`>=`). Only the setting for the selected persistence mode is editable; unused values are retained for replay. Seconds mode uses elapsed span and its inherent minimum of two observations, without adding the sample-mode count as a second requirement. There is no smoothing. The local trace is `(y−b)/(1+b)`, where `y` is the fixed-reference fractional trace and `b` its local baseline mean. Therefore a local threshold `T` is drawn on the global trace at `b+(1+b)×T`.

**Provisional slow evoked: 2 samples** starts at a 0.10 fractional floor, 3 times the cell's noise and 2 qualifying samples in a row. It is a starting protocol to validate on the experiment's controls, not an established optimum for 50B11 or every indicator. The length can instead be given in seconds: last timestamp minus first timestamp is the duration, so a one-second span at 2 Hz needs at least three qualifying samples. Missing values and excessive gaps break the run. Version 2 requires complete window coverage and enough reference samples; unavailable coverage is unscorable with a reason, rather than treated as no response.

**Custom version 2** keeps all settings independently editable. Timing edits retain different stimulus/control threshold, duration and noise rules. **Legacy sample rule (starts at 2)** exports actual schema 1 and calls the historical responder engine, including its historical endpoint handling. It is not version 2 with a two-sample setting. Legacy mode uses an immediately preceding reference and its optional control remains KCl. Version-2-only fields are locked or labeled unused; editing the start of the legacy response window also moves its reference end and onset. Historical settings TSV files still follow the same legacy path. New explanatory metrics/QC annotations do not change historical classifications or counts.

The browser's **Import protocol JSON / Export protocol**, or the native **Load protocol / Save protocol**, exchange declarative JSON with SimpleCa²⁺. Files record schema and engine version, name, validation status, the noise estimator, each window and optional field overrides. Files written by the plugin name the estimator at the top as well (`sd_estimator`); SimpleCa²⁺ reads the copies in the windows. Imported overrides are retained in the browser's expandable protocol settings; the native window also shows a recording match count and offers **View field timing overrides**. Overrides can be explicitly cleared. A matching override changes that recording's timing while preserving its rule. `validated_by_user` is a user declaration, not certification by the program. Unsupported schema, reference, engine or rule semantics are rejected, and so is an estimator recorded with another engine version than the earliest that defines it. The browser's import makes one allowance: when a file names an estimator at the top (`sd_estimator`) and its windows say `sample_sd` with engine version 2.0.0, the name at the top stands, because the page writes its own settings that way. **Load protocol** refuses such a file. The whole-trace estimator was added in this plugin, so the SimpleCa²⁺ app refuses a protocol that uses it as an unsupported engine version. Protocols on the baseline SD go both ways.

### Noise

A protocol names what a cell's noise is taken from (`SD_estimator`). Both estimates are fractions of the local reference, like the rise they are compared with.

| Estimator | Noise | Recorded with engine |
|---|---|---|
| `larger_of_baseline_sd_and_trace_noise` | The larger of the sample SD of the local baseline and the whole-trace noise. Every protocol the plugin makes uses it, including a version 2 rule made from a legacy one | 2.1.0 |
| `sample_sd` | The sample SD of the local baseline alone. The only estimator before engine 2.1.0, and the legacy rule's | 2.0.0 |

Whole-trace noise is 1.4826 × the median absolute deviation, about their median, of the differences between consecutive samples over the whole recording, divided by √2. It measures frame-to-frame noise, so a response moves it little. A difference counts when both samples are finite and no further apart than the maximum gap. A baseline of a few frames can come out quieter than the cell is; taking the larger of the two keeps such a cell from being called on two chance samples. A cell with fewer usable differences than the minimum baseline samples keeps its baseline SD and is flagged `WHOLE_TRACE_NOISE_UNAVAILABLE`.

An imported protocol and every saved analysis keep the estimator they were saved with. Settings remembered for a recording keep an estimator they name. Settings remembered before the plugin carried engine 2.1.0 name none, because there was only one: their timing and thresholds are filled in, noise is taken as a new protocol takes it, and the status line says "Noise is now the larger of baseline SD and whole-trace noise." The native window shows the noise in use under the protocol name. The browser page does not yet show or change it; when remembered settings that name the baseline SD are filled in, its status line ends "Noise: baseline SD, as saved." for as long as the settings use it, and the finish message of an analysis on the baseline SD ends the same way. A protocol records the earliest engine release that defines its rule, not the engine that wrote or runs it, so a `sample_sd` protocol keeps its hash and gives the same tables under engine 2.1.0 as under 2.0.0. Any other pairing of estimator and engine version is refused.

## Eligibility, quality and percentages

A cell with no finite positive normalization reference, or F0 ≤ 0.000001, is excluded using the shared normalization rule. A missing local background is a technical exclusion. Missing/insufficient local baseline data, incomplete response coverage or an invalid local reference can make an individual window unscorable. The cell remains in the registry and quality/call exports.

Low F0 relative to raw baseline SD, zero baseline SD and other review flags are warnings. They do not automatically remove cells. There is no automatic peak-outlier filter. Zero SD can leave the amplitude floor as the active requirement; the warning remains available for review. A noise-only rule with zero estimated SD is unscorable unless a justified nonzero measurement-noise floor is supplied.

For each window, percent responding is `100 × Responded / (Responded + Did not respond)`. That denominator is **Evaluable**. Registered, Excluded and Unscorable are exported separately. Zero evaluable cells produces an unavailable percentage, not zero. The optional control-positive population includes only control responders that are also evaluable for the primary stimulus; its numerator is the primary responders within that population. A control nonresponse is not automatically classified as a dead cell or removed from the primary percentage.

`cohort_flow.csv` distinguishes all accepted ROIs, premeasurement exclusions, cells registered for analysis and normalization exclusions. `responder_counts.csv` adds window-specific evaluability. Selection based on response cannot be repaired by a threshold after the fact.

## Review the completed analysis

- **Traces:** fixed-reference ΔF/F₀ for the selected cell and the mean ± SEM of cells. The browser can show every cell behind the mean: responders in the responder colour, the other cells in gray. Hover or click to identify a cell; hold Ctrl or ⌘ and scroll to zoom the time axis, and double-click to reset. The automatic Y range covers every mean ± SEM that is drawn and the selected cell. With single cells drawn it also takes in their bulk (the 2nd percentile of their lows to the 95th percentile of their highs, each cell by its own 1st to 99th percentile, over cells that are neither excluded nor below −1), but no further beyond the means than one and a half times their own height; a trace that runs past it ends at the plot's edge. With one cell, the plot draws its required rise; **Thresholds** adds the threshold that did not set the required rise (the minimum rise or the noise threshold) and the baseline mean. Every line and band is named once, in the legend. The range is a display choice, not a cell exclusion or a change to peak/AUC measurements. While **Leave out … below zero** is ticked, those cells are also left out of the traces and the mean on screen; saved tables are unchanged.
- **References and qualifying runs:** normalization, local baseline, response windows and qualifying evidence refer to the completed analysis. The local threshold is transformed to the global trace axis as described above. The selected call supplies its status, reason, threshold and run timing; editing a draft must not redraw an old result using new thresholds.
- **Time and movie:** in **Recording** view, the slider, **Play** and the plot cursor move together. **Change from baseline** shows that frame minus the average of the normalization baseline frames, lightly smoothed for viewing. **Static colour overview** shows the Step 2 picture and stays still; movie playback is disabled in that view. The native fallback labels these views **Movie: as recorded**, **Movie: change from rest** and **Static colour overview**. **Zoom to cell** follows a selected cell. In the browser the picture has zoom controls on its corner (**+**, **−**, the zoom level, **Whole picture**, **Zoom to region**), the keys +, − and 0 while the pointer is over it, a pinch or Ctrl/⌘ + scroll about the pointer, a drag to move it when zoomed in, and a small map of the whole field with a frame around the part on screen. **All outlines** controls the overlay; **Outlines** draws it by response call or plain white, and **Number cells** writes each cell's number in its outline; saved pictures and frames follow both, and the file kept beside them records the outline colours and whether the cells were numbered. **Area** (in the picture's Export menu and in Save frames…) saves the whole picture or the area on screen; a picture of an area has a scale bar, and its record gives the area in pixels and in µm. **Save frames… › Baseline and peak** saves one picture of two frames side by side at one brightness, and its record names both frames and the gray levels they are shown between. These operations affect display only, not measured fluorescence, normalization or response calls.
- **Cells and response groups:** click a trace, picture outline or heatmap row, choose a cell in the list, or use previous/next navigation. The browser's **Show** filter and headline tiles restrict the displayed group. They do not change the registered/evaluable denominator. Outlines and status colours use the saved calls for the selected stimulus window, after review for the primary stimulus.
- **Heatmap:** one row per cell. Blue–white–red, the default, is white at ΔF/F₀ = 0 and scales its two sides separately; the other palettes start at zero. The colour range is taken from the cells that are neither excluded nor below −1: their 1st to 99th percentile, or their smallest to largest value, rounded outward. Values beyond the range take the end colour, and the colour bar marks that end with ≤ or ≥. Order by response call (largest rise in the response window on top), onset time (responders only; the rest as by response call), time to peak, peak amplitude or original cell order. In every order but the original one, cells below −1 come last, within their group when the rows are grouped by call; a mark beside the rows shows them. The key gives the number of cells in each group; the groups of the primary stimulus follow the call after review. **Cell names** prints the names beside the rows, every few rows when the rows are thin, and **Hide excluded cells** leaves their rows out. Missing values and acquisition gaps remain visible. The native fallback takes its colour limit from the same cells and orders its rows by the same rule. These are display choices: changing palette, range, order or hidden rows does not drop cells from the result tables. The file kept beside a saved heatmap lists the cell of each row and the colour range used.
- **Headline tiles:** the saved primary-window percentage and its evaluable denominator, plus registered, excluded and unscorable counts. With review marks the percentage is the one after review, with the count before review beside it. The stimulus name identifies that primary summary even when another window is being inspected. The saved tables remain the authoritative record.
- **Quality, ROI registry and call tables:** reasons and warnings remain beside each cell. Whole-recording metrics and stimulus-window metrics are separate. The browser supports table sorting; a selected row can return to that cell's trace. The native fallback retains trace, movie/picture, heatmap and table review without changing Step 2 ROIs.

Editing a draft protocol or settings does not change an already completed result. The browser shows **Changes pending** and offers **Apply changes & reanalyze**; results, movie timing and exports continue to use the last completed analysis until the new run succeeds. Timestamp and diagnostic file content signatures include changes or deletion at the same path. Displays and plot exports remain bound to the completed analysis, with provenance identifying its input and applied protocol. The native **Save plots as PNG** also writes `plot_provenance.json`, containing the manifest checksum, protocol identity, selected cell/window and whether edits were pending. Failed or cancelled reruns keep the preceding completed tables. Partial runs have no `COMPLETE` marker and are not displayed as completed results.

## Metrics, diagnostics and biological units

Legacy **AUC** is the signed whole-recording integral and legacy **Time-to-Peak** is the recording timestamp of that peak. Those columns are not repurposed. New window metrics include local fractional peak, signed local AUC in fraction·seconds, actual covered duration/fraction, response latency from application, peak latency, run duration, run samples and confirmation time. AUC uses observed valid sample intervals and does not interpolate through excessive gaps or invent signal outside the recording. Peak outliers remain visible. Legacy annotations use the actual historically clipped endpoint and explicitly identify the annotation engine.

**Save diagnostic templates** creates a sensitivity grid and a negative-control-window template in the measurement folder. Enter genuine unstimulated/vehicle times in the latter. Loading a grid reruns the shared engine for each declared scenario; loading negative-control windows reports their apparent response fraction. These are separately labeled exploratory diagnostics, not replacements for the applied rule or a claim of statistical specificity. They require version 2; selecting/importing legacy detaches diagnostic file selections and explains why. Files are snapshotted for reproducibility.

A biological unit is the independent culture, animal or preparation. Multiple cells and fields from it are nested observations. The recording's unit and condition are exported with counts; the shared summary function pools fields within an assigned unit and reports unit percentages separately from cell-pooled percentages. Step 4 handles one recording per run, so cross-recording aggregation belongs in SimpleCa²⁺ or a subsequent analysis using the exported metadata. Blank unit IDs create an explicit unassigned record and no invented biological N. Trace SEM remains descriptive cell SEM.

## Checks on the calls

After the engine has finished, the plugin checks every evaluable cell and writes `<recording>_call_checks_<analysis folder>.csv` beside `<recording>_percent_responding_<analysis folder>.csv`. A check is a flag for review. It never changes a call, a count or a percentage, and the analysis folder itself is not written to. The same table is made from the browser page and from the Fiji window. Both views show the flags for the primary stimulus only; the control window shows none. The page lists each flag among the cells flagged, with a filter for each code: Possible passing object, which takes `passes through` and `crosses the cell`, Rise on the edge, Field moved and Short separate crossings. The list shows every flagged cell, and in a short window the whole list scrolls. The flags are also in the cell panel, where a click on a flag moves the movie to the first of its `frames`, the first and last frame its text names in `checks.cells[cell].flags`, and the tooltip says "Go to frame N"; when `frames` is null, for short separate crossings, it goes to `firstFrame`, the first frame of the event. An answer without `frames` has them read from the flag's text. The Fiji window shows the flags under the selected cell's call line and goes to the same frame in the Traces tab, or moves the time cursor of Around the cell when that tab is shown. An evaluable cell that was not checked while the rings were measured says `passing object not checked: <why>` in the page's cell panel and under the Fiji window's call line. `checks.note`, when there is one, is shown once in the page's list of flagged cells, on the control window too, and at the end of the Fiji window's finish message. When the note is the list's only item, the button that opens the list reads "Passing objects not checked" when the rings were not measured, else "Checks note", and the note leads the list. On the page the flags also join the Flags column of the calls table and of Cell quality, after the engine's own and in the same words, for example "Duration under a frame · Possible passing object"; pointing at it gives the codes. In the Fiji window their codes join `QC_flags` on the calls, response window metrics, Cell quality and whole-recording metrics tabs, and a cell cut by its column shows its whole text when pointed at. In the calls table they are on the rows of the primary stimulus only. The page's Exports of the calls table, the response window metrics, Cell quality and the whole-recording metrics put `checks.cells[cell].codes` into `QC_flags`, after the engine's codes, joined with `checks.join`, "; ", in the first two and with ";" in the per-cell tables, as the engine joins its own; the record beside such an Export gains `qc_flags`: "QC_flags includes the codes of the call checks, after the engine's codes." Without a code added the Export and its record are as before. An analysis without checks shows nothing about them. While the checks run, the page's Cancel is grayed out. Once the engine has finished, the analysis can no longer be cancelled: the checks run to the end.

### What Measure and save records around each cell

In the same pass over the frames as the cells and their backgrounds, the mean raw gray value of 25 fixed sets of pixels per cell is measured:

| Zone | Pixels |
|---|---|
| Near ring, 8 sectors | Outside the outline, more than 0.645 µm and up to 6.45 µm from it |
| Far ring, 8 sectors | Outside the outline, more than 6.45 µm and up to 14.19 µm from it |
| Core | Inside the outline, deeper than the median depth |
| Rim, 8 sectors | The other pixels inside |

Sectors are 45° wide and centred on right, lower right, bottom, lower left, left, upper left, top and upper right, seen from the mean x and y of the outline's pixels. Distances are Euclidean between pixel centres: outside, to the nearest pixel of the outline; inside, to the nearest pixel that is not in the outline, with the picture's border counted as outside. Both rings leave out every pixel within 1.29 µm of another measured outline and keep bright pixels. A zone with fewer than 12 pixels is not used, whatever the reason: a sector mostly covered by other outlines, one cut by the picture's border, or a small rim. The outlines' pixels are the same ImageJ masks the cell values are measured with.

The widths were set as 1, 10, 22 and 2 pixels on recordings at 0.645 µm per pixel. They are kept in micrometres and turned into pixels with the recording's pixel size, to a hundredth of a pixel. A recording without a pixel size in micrometres takes the pixel values as they are, and so does one whose pixels are not square, within 1 %; `what_was_done.txt` says which. The unit is read as micrometres by the same test as the 100 µm scale bar.

| File | Content |
|---|---|
| `<recording>_ring_and_core_gray_values.csv.gz` | One row per frame. `Frame`, then for every cell 25 columns `<cell>\|near_right` … `\|near_upper_right`, `\|far_right` … `\|far_upper_right`, `\|core`, `\|rim_right` … `\|rim_upper_right`. Two decimals; empty where the zone has fewer than 12 pixels |
| `<recording>_ring_and_core_pixels.csv` | One row per cell: `Cell`; `ROI_sha256`, the outline as the ROI registry names it; `Area_pixels`; the pixel count of each zone; `Near_ring_sectors_usable`; `Raw_table_sha256`, the hash of `<recording>_gray_values_raw.csv`; `Ring_and_core_values_sha256`, the hash of the values table above; `Pixel_size_um`; the three ring widths in pixels; and `Other_outline_margin_px`, the margin left around other outlines |
| `<recording>_field_movement.csv` | `Frame`, `Displacement_px`, `Shift_x_px`, `Shift_y_px`: the shift of the field at every frame as the movement check of Step 1 measures it, and how far that is from where the field sits for most of the recording. The displacement is the middle value of five frames, with a jolt of one or two frames kept. Written only when Step 1 could measure the movement, which needs a picture at least 196 pixels wide and high and 3 frames or more |

`what_was_done.txt` gains one line, "Around each cell: …". No other file of Steps 1 to 3 changes. When one of the three files cannot be written, none of them is left, every other file is saved as it would be without them, and the line says "Around each cell: the rings and the core were not saved: <file> could not be written. The cell measurements are unchanged." The exception goes to Fiji's Log.

Step 4 uses these files only when they name the cells, the outlines and the raw table of the measurement being analysed, and when the values table is the one the pixels table names. When an analysis runs and they are missing or belong to another measurement, they are measured then with the same code and saved beside the tables, provided the recording is open in Fiji and gives the saved raw gray values on its first, middle and last frame. In practice this is when the rings could not be saved at Measure, or the files were taken away or replaced since: Step 4 runs on the measurement just made. A recording measured with an earlier version has no ring files and must be measured again to be checked. Otherwise the passing-object check is not made and every row says `not checked` with the reason. The field movement is not measured again at this point for files that belong to the measurement.

### The rules

Only the event of the largest rise is looked at. The F0 frames are the analysis's own normalization baseline frames.

- **Traces**, in gray levels: the cell is raw minus its background minus its mean over the F0 frames. A zone is its mean minus its own F0 mean minus the change of the cell's background. Both are averaged over 3 frames. A cell or zone with a value that is not a number is not used.
- **Event**: the frames around the peak of the call where the averaged cell trace is at or above half its value at that peak. A dip of up to 3 frames does not end it. The cell's rise is its value at the peak.
- **Noise of a zone**: the larger of the SD of its averaged trace over the F0 frames, and 1.4826 × the median absolute deviation of the frame-to-frame differences of its unaveraged trace over the whole recording, divided by √2 and by √3.
- **Passes through**: a near- or far-ring sector rises in the 10 s before the event and a sector at least 90° away rises in the 10 s after it. Each rise is at least the cell's own rise and at least 5 × that sector's noise, is gone while the cell is up, with its mean over the event at most half its peak, and is at a frame where the cell is still below half its rise. Text: `possible passing object, frames 201 to 210`, the frames of the event.
- **On the edge**: over the event the core rises less than 0.25 × the whole outline, and the near-ring sector outside the rim sector that rises most rises at least as much as that rim sector and at least 5 × its own noise. No neighbouring sector stands in for a sector that is not usable, and without a usable core the rule is not applied. Text: `rise on the lower right edge, not in the cell, frames 92 to 149`: the frames of the event, widened on each side for as long as that ring sector stays above half its mean over the event. The text never says "object": in the recordings the rule was set on, most such rises were a neighbour without an outline.
- **Field moved**: when one of the two rules applies, the field's shifts from 10 s before the event to 10 s after it are looked at. The field counts as moved when at one of those frames it is 8 pixels or more from where it was over the F0 frames, with the displacement as `field_movement.csv` gives it, or, when no frame is, when it moved 8 pixels or more between two of those frames, each taken as the middle value of five frames. When the field moved within the F0 frames themselves by 8 pixels or more, it is counted from where it sits for most of the recording instead. The row then reads `field moved, frames 28 to 35` instead of the rule's text: the longest stretch of displaced frames, or the two closest frames it moved that far between. Its detail says how far, every displaced stretch, and what would otherwise have been written.
- **Crosses the cell**: the cell's trace is averaged as above, and the frames around the peak where it is at or above a quarter of its rise, with a dip of up to 3 frames, make the window; it needs 2 frames or more. The core, the 8 rim sectors and the 8 near-ring sectors are weighted by their pixels and by their centres, the mean x and y of each zone's pixels from the outline's, to give the centre of the rise at every frame, after the background and the F0 mean are taken off and the 3-frame average. The centres over the first and the last half of the window give the start and the end. The cell is flagged when the travel from start to end is at least half the outline's width in that direction, the steps between frames go that way for at least 0.6 of their weight, the travel is at least 3 × its noise, from the frame-to-frame differences over the whole recording, and the outline's centre lies between the start and the end. The zone centres are made again from the outlines of the analysis at check time with the zone code of Measure, and every zone's pixel count must equal the one in `ring_and_core_pixels.csv`; otherwise this rule is not applied to the cell and the detail says "crossing not checked: the outline does not match its ring file", or why the outlines are not at hand. The other checks are made all the same. Text: `possible passing object, frames 78 to 81`, the frames of the window, from a quarter of the rise on each side, so they can start before and end after the frames of the event; detail: "the rise crossed the cell from the left to the right, 0.84 x its width". When passes through or on the edge already flags the cell, that flag stays and its detail adds "; also crosses the cell ..." when the field did not move over the window. Field moved is looked at as for the two rules above, over the window. The rule does not see an object that covers the cell and its ring at once, or one that comes to rest on the cell.
- **Short separate crossings**: for a responder, the stretches of samples at or above its required rise inside the response window are counted from the engine's own columns, `Threshold_increase`, `Baseline_mean`, `Local_reference_relative`, `Start_s`, `Effective_end_s` and `Max_gap_s`, and the saved normalized trace. Three or more stretches, none longer than 2 samples, give `short separate crossings`.

A stretch of one frame reads `frame 28`. The 10 s span was set as 10 frames at 1 frame per second and is turned into frames with the median frame interval of the analysis. The 3-frame average and the 3-frame dip are counted in frames.

### What the check cannot see

- It looks only at the event of the largest rise. In 53 of 330 responders of the nine test recordings the samples that made the call lay outside that event.
- By eye, 14 capsaicin and KCl responders in those recordings were objects. The check flagged 11: 9 of 9 in outlines of 900 pixels or more, 2 of 5 in outlines under 700 pixels. Two of the 11 were found only by crosses the cell.
- It misses most objects that cross in 2 frames, and objects that come to rest inside the outline and stay.
- Each near-ring sector lost to a neighbouring outline lowers the chance of a flag. `Near_ring_sectors_usable` and `Area_pixels` are in the table for that reason.
- On the edge cannot tell an object resting on the edge from a neighbour without an outline that responds beside it.
- A flag is not proof of an object. Of 296 ATP responders in three recordings 2 were flagged and neither was an object. The thresholds were set and tested on the same nine recordings.
- Crosses the cell was designed on eight of these recordings: three designs that followed the centre of the rise inside the outline alone were tried and dropped there, and the rule kept follows it over the outline and its near ring. There it flags 2 of the 5 objects the other two rules miss, P1 Run2 cell 90 and P1 Run3 cell 146, none of 228 ATP responders or 20 other responders without an object, and 2 of 880 non-responders without an object, C1 Run2 cells 28 and 34. On C2, kept aside, it flags none of 68 responders and 144 non-responders. Two objects are too few to say how often it finds one. Of the 4 objects in outlines under 700 pixels that the other two rules miss, it flags 1, P1 Run2 cell 90.

A sentence for a Methods section: "Responder calls were checked for bright objects passing through an outline, using the fluorescence in sectors of two rings around each outline and in its core and rim, and for a rise whose centre moved across the outline; flagged cells were reviewed in the movie. The check examines only the largest rise of each cell, does not detect most objects that cross within two frames, and does not detect objects that remain inside the outline."

## Review marks

An evaluable cell of the primary stimulus can be marked the other way after review: `Responded` to `Did not respond` or the reverse, with a reason: `Noise`, `Movement`, `Passing object`, `Bad outline` or `Other`. `Other` needs a note. A note is one line of plain text, at most 120 characters, without hidden characters, and cannot start with =, +, - or @, which a spreadsheet would read as a formula; spaces at either end are taken off. A mark can be removed. Excluded and unscorable cells cannot be marked. The control window is never reviewed.

| File, beside the percent table | What it holds |
|---|---|
| `<recording>_reviewed_calls_<analysis folder>.csv` | One row per mark: `Cell`, `Automatic_call`, `Reviewed_call`, `Reason`, `Note`; `Time`, ISO 8601 to the second with the offset; `Analysis`, the analysis folder's name; `Responder_calls_sha256`, the hash of that folder's `responder_calls.csv`; `ROI_sha256`, the outline as its ROI registry names it; `Carried_from`, empty for a mark made in this analysis, else the analysis the mark was made in; and, only while the file holds an automatic mark, `Marked_by`, `manual` for a mark set by hand or `automatic`. With manual marks only the file is written as 2026.11.24.1 writes it, and 2026.11.24.1 reads it as before. Present only while there is at least one mark. A file written by 2026.11.24.1 reads as manual marks. 2026.11.24.1 does not read a file that holds an automatic mark: it says the review file cannot be read, does not use its marks, cannot change them, does not carry them over, writes the percent table again without the after-review columns, and asks to move the review file out of the folder. Do not move it: open the analysis with this build, which writes the columns again. |
| `<recording>_percent_responding_<analysis folder>.csv` | With marks: the same rows and columns, then `responded_after_review`, `percent_responding_after_review`, `responded_without_them_after_review`, `percent_without_them_after_review`, `cells_reclassified`. Without marks: as before, byte for byte. |

## Files and source provenance

Each successful run gets a new `SimpleCa-date-time-id` folder. It contains the input and optional timestamp/ROI/diagnostic snapshots, settings, `protocol.json`, `applied_protocol.json`, normalized traces, mean trace, metrics, quality, ROI registry, cohort flow, calls/counts, window metrics, replicate/group counts, metadata, manifest and log. Optional diagnostic outputs are separate. Previous runs are not overwritten.

The bundled `utils.R`, `response_protocols.R` and `responders.R` began as [SimpleCa²⁺ commit b92d4ce](https://github.com/samgillman/simplecaapp/tree/b92d4ce98ddab3fceac352179703c1f48f044c90), under its MIT licence. The whole-trace noise estimator and response engine 2.1.0 were added in this plugin and are not in SimpleCa²⁺. `analysis/provenance.tsv` records that commit, the change and the SHA-256 of each file, and every analysis manifest repeats them. The adapter uses their normalization, metrics, protocol import/validation, response calls and summary functions. Source SHA-256 hashes, plugin/R/jsonlite versions, actual input checksum, applied protocol and units are saved with results. `settings.tsv` and `analysis_manifest.csv` name the noise estimator (`sd_estimator`; `sample_sd` for the legacy rule); the manifest also gives the engine's own sentence for it (`noise_rule`), the engine that made the calls (`engine_version`) and the release the protocol is recorded with (`protocol_engine_version`). With the whole-trace estimator, `responder_calls.csv`, `sensitivity_calls.csv` and `negative_control_calls.csv` have three more columns, placed last so that every other column keeps its position: `Whole_trace_noise`, `Whole_trace_noise_samples` and `Noise_source` (`Baseline SD`, `Whole-trace noise` or `Noise floor`; blank where the noise was not measured). Read `Noise_source` together with `Threshold_source`, which names the term that set the threshold: `Floor` is the minimum rise, and `Baseline noise` is the SD multiplier times the noise, whichever estimate the noise is. A threshold was set by the whole-trace noise when `Threshold_source` is `Baseline noise` and `Noise_source` is `Whole-trace noise`; the native window's line under a cell's plot names the estimate. A `sample_sd` run has the same columns as before. The shared canonical protocol MD5 is an identity for comparison, not a security signature. Managed package records remain in the environment's `conda-meta` directory.

Synthetic tests cover independent hand-calculated response outcomes as well as parity with the shared engine. CI is configured for managed runtime checks on Windows, macOS and Linux and native GUI checks on Windows/Linux. Browser acceptance is a separate Playwright gate described in the release guide; server and JavaScript syntax checks alone are not browser validation. These checks do not establish biological sensitivity/specificity or replace acquisition-specific control validation.

## Step 4 editing and quality review

Invalid frame rates, frame ranges, reversed windows and negative thresholds show inline errors before analysis; submission runs the authoritative validation again. A timestamp CSV takes priority over FPS. Elapsed-time and legacy rule types retain separate drafts when switching. **Discard changes** restores the complete applied draft, including uploaded file contents, or the starting draft before the first analysis. Completed results, movie timing and exported plots keep their applied settings until a new analysis succeeds.

On the page, a newly enabled positive control starts blank: enter its **Stimulus after frame**; its **Baseline** and **Response window** rows then follow it, as for the primary stimulus. In the Fiji window it starts with placeholder times after the primary response window; replace them with the actual timing, which the software cannot know. Recording-coverage and baseline-overlap warnings do not silently alter a protocol.

The quality summary and per-cell feedback show saved flags, including `DURATION_BELOW_SAMPLE_INTERVAL` and `reference_below_3_baseline_sd_review`. A separate review indicator identifies saved traces below −1. These display diagnostics do not recalculate response calls or add exclusions. **Needs quality review**, **Excluded** and **Unscorable** are separate filters. The flags of the checks on the calls join the same list, with a filter for each rule, and while there are review marks **Marked** is a filter too. A low reference can make fractional values unstable; a value below −1 corresponds to negative background-corrected fluorescence when F₀ is positive. Inspect background and baseline stability before interpreting these traces.

**Response-window metrics** provide the applied per-stimulus peak, latency and signed AUC. **Whole-recording metrics** retain their established definitions: `AUC` integrates the whole recording and can be negative under downward drift; `Time_to_Peak` is the recording timestamp; `Rise_Time` uses 10–90% crossings after the display baseline, which can be sensitive to baseline noise. The interface labels these definitions rather than changing old values. Use `Peak_latency_s` for time from stimulus onset and `Window_AUC_fraction_s` for the declared response window.

The calls table, the whole-recording and response-window metrics and the cell quality table start with their core columns; the responder counts are shown turned, a row for each column. **Show all saved columns** exposes the complete table; saved CSVs always retain every column under their saved names. On screen a column is named in words with its unit, and pointing at its header gives what it measures and its saved name. Numbers are rounded by unit (time 2 decimals, ΔF/F₀ 3, percentages 1 with "%", gray levels 2); pointing at a number gives the saved value. Columns that are the same by definition (`Run_start_s` and `Onset_s`, `Response_Amplitude` and `Peak_dFF0`, `Reference_value` and `F0`) are shown once unless every column is shown. The response timing of a cell that did not respond is a dash, its saved value in the tooltip. The first column (Frame and Time on Processed data) stays in place when a table scrolls sideways; blanks sort last. The calls and counts tabs have their own Export, which saves or downloads the saved table as a CSV; while there are marks the calls table's Export adds Reviewed_call, Review_reason and Review_note on the right. Empty tables explain that no rows were saved. Short windows can scroll vertically while plots and captions keep a readable height.
